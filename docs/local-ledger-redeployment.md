# LOCAL 준비 상태 재배포 검사

## 범위

최초 R2 → LOCAL 전환 검사는 R2 0건만 허용하므로 이미 LOCAL로 전환한 서비스의 재배포를 차단했다. 이번 변경은 **계정 작업이 중지된 준비 상태**의 재배포만 지원한다. 탈퇴·복구·파기 활성화, 저장소 이동, 키 교체, 백업 삭제는 포함하지 않는다.

## 검사 순서

1. 현재 API·배치가 실행 중이며 유지보수 상태인지, 모든 계정 작업 플래그가 꺼져 있는지 확인한다.
2. 배포 후보 설정을 표준 입력으로 받는다. 크기를 제한하고 Base64/고정 형식만 파싱하며 셸로 실행하지 않는다.
3. 현재 설정과 후보의 저장소 ID·경로·realm·DB 세대·키 묶음·활성 키를 대조한다. 대상 서비스의 체크포인트 토큰도 그대로인지 확인한다. 이 배포에서 키/토큰 교체는 금지한다.
4. 대상 서비스가 R2라면 기존의 US R2·LOCAL 0건 검사를 유지한다. 대상이 LOCAL이면 API·배치 모두 동일 LOCAL 저장소여야 한다. LOCAL의 R2 연결 정보 잔존도 차단한다.
5. LOCAL 재배포는 독립 GitHub 체크포인트와 파기 의도·카탈로그를 대조하고 암호문을 인증한다. 과거 DB 세대의 완료 증빙도 빠짐없이 확인한다. 전체를 두 차례 읽어 체크포인트와 암호문 목록이 변하지 않았는지 확인한다.
6. 실제 서비스 이미지에서 네트워크 없는 검사 컨테이너를 실행해 정확한 bind 경로·마커·권한·잠금·파일 읽기를 확인한다. DB·Redis·Spring·비밀키를 전달하지 않는다.
7. 검사 전후 현재 컨테이너의 ID·이미지·시작 시각·재시작 횟수·설정·마운트를 비교한다. 모두 통과한 뒤에만 배포 워크플로가 운영 설정을 변경할 수 있다.

### 실제 서버에서 확인한 마운트 순서 오탐 보완

2026-09-09 연속 검사에서 배치만 간헐적으로 차단됐다. Docker 상태를 100회 조회해 동일한 두 마운트의 배열 순서가 바뀌는 현상을 재현했다. 내용이 같아도 배열 순서가 다르면 기존 지문이 달라지는 문제였다. 마운트 목록만 모든 필드를 유지한 채 정렬하여 지문을 계산한다. 실제 경로·쓰기 권한·종류·중복 마운트 변경은 여전히 차단한다. 실패를 무시하거나 재시도로 덮지 않는다.

## 제한과 실패 처리

- 독립 체크포인트가 없거나 변경되면 실패한다. 현재 파일만 보고 새 기준을 자동 생성하지 않는다.
- 누락·손상·키 불일치·고아 완료 증빙·잘못된 파일·권한·저장소 식별값은 실패한다. 무시하거나 자동 복구하지 않는다.
- 최대 파기 의도 5,000건, 모든 종류 합계 10,000개 객체. 상한 초과는 실패하며 별도 용량 검토가 필요하다.
- Java 검사 제한 150초, Docker 파일 접근 검사 40초. 시간 초과·원격 검증 실패는 배포 중단이다. 로그에는 합격 여부만 출력한다.
- 파일 내용·대장·체크포인트 쓰기는 없다. 파일 잠금 및 디렉터리 fsync는 기존 저장소 구현의 안전성 검사다.
- 활성화된 운영 상태의 무중단 재배포는 지원하지 않는다. 기록 작성자 중지/동시 배포 제어는 별도 작업이다. 두 서비스 배포를 동시에 실행하지 않는다.
- 현재/후보 키 JSON은 정확히 일치해야 하므로 표현 순서만 달라도 차단될 수 있다. 검토 없이 검사를 우회하지 않는다.
- Docker 검사는 현재 서비스 이미지의 파일 접근 검증이며 배포 후보 이미지 전체의 실행 검증을 대체하지 않는다.

## 설치·배포 순서 및 되돌리기

아직 설치하지 않은 새 도구와 워크플로는 함께 검토해야 한다. 설치 경로는 비공개 운영 절차에서 관리한다.

1. 새 라이브러리를 기존과 다른 버전 디렉터리에 설치하고 해시·소유권·권한을 확인한다. 기존 라이브러리는 보존한다.
2. 새 검사기를 별도 경로에서 직접 검증한다. 현재 설정과 같은 후보를 사용한 시험은 후보 GitHub Secrets의 검증을 대신하지 않는다.
3. API·배치의 동시 배포가 없는 동안 기존 실행 파일을 보존하고 새 실행 파일로 전환한다. 운영 앱을 재시작하거나 계정 기능을 켜지 않는다.
4. API·배치 워크플로에 후보 설정 표준 입력 전달을 반영한다. 구 워크플로는 새 검사기에 입력하지 않아 실패한다. 검사 생략으로 호환성을 맞추지 않는다.
5. 별도 승인 후 한 서비스씩 실제 배포·건강 상태·로그인 복귀를 확인한다.

설치 실패 시 기존 실행 파일/라이브러리를 복구한다. 이는 이전의 R2 0건 전환 검사로 돌아가는 것이므로 LOCAL 재배포는 다시 차단되는 안전한 중지 상태다. 대장 파일이나 DB를 되돌리거나 삭제하지 않는다.

## 자동 검증

- Python: 최초 전환/LOCAL 분기, 후보 입력 형식, 현재·후보 설정 차이, 활성화 차단, 컨테이너 마운트/UID, 검사 실패·실행 상태 변화, 자식 프로세스 비밀값 최소화.
- Java: 0건/기록 있는 경우, 모든 세대 완료 증빙, 누락·변조·고아 증빙, 키/DB 세대 불일치, 체크포인트 누락·변화, 완료 증빙만 변한 경우, 처리 상한, 중복 JSON 키·비문자 키·후행 JSON 차단.
- API·배치: 실제 워크플로와 생성 템플릿 일치, 비밀값 전달/중지 플래그 유지, 기존 Tunnel 전송 및 셸 구문 검사.
- 운영 설치·실행 성공은 별도 증거를 확인한 후 기록한다. 로컬 테스트 통과만으로 운영 검증이나 WBS 전체 완료로 표시하지 않는다.

# 공공데이터 좌표 메타데이터 묶음 조회

공공데이터 한 페이지를 처리할 때 관리번호별로 기존 주소·좌표 메타데이터를 조회하던 경로를 최대 250개의 고유 관리번호씩 묶어서 읽는다. 다른 저장·외부 API 경로의 비용까지 줄이는 변경은 아니다.

## 보존하는 동작

- 빈 관리번호는 조회·지오코딩하지 않는다. 조회 키의 정확히 같은 중복만 제거하며 반환 시설의 순서·중복은 유지한다.
- 관리번호를 Java에서 대소문자·공백 정규화하지 않는다. DB가 기존 단건 조건으로 비교하고 요청 순번으로 원래 키에 결과를 연결한다.
- 관리자 확정 좌표·기존 좌표·한쪽만 존재하는 좌표를 유지한다. 두 좌표가 모두 없을 때만 도로명 → 지번 순서로 기존 지오코딩을 실행한다.
- 실패한 시설은 기존 실패 상태·시각 규칙으로 처리하고 다음 시설을 계속 처리한다.
- 메타데이터는 이번 페이지에서만 재사용한다. 다음 페이지·재실행에서는 DB를 다시 읽는다. DB 스키마·저장 보호 SQL·회원 및 대장 설정을 변경하지 않는다.

## 검증

합성 시설 1,000개의 주소·좌표·출처·해시·시각·NULL 결과를 기존 단건 SQL과 비교하고 메타데이터 조회 호출이 1,000회에서 4회로 줄어드는지 검사한다. 빈 키·중복·없는 키·너무 긴 키와 다음 페이지의 수정 반영도 검사한다. H2뿐 아니라 격리된 MySQL CI에서 문자 비교 규칙이 다른 테이블들을 검증하고 저장 시 관리자 확정 좌표·숨김 시설 보호 회귀를 실행한다.

MySQL 검사는 고정된 로컬 CI 포트와 전용 합성 자격 증명만 사용하며 새 임의 스키마만 생성·정리한다. 운영 DB·실제 공공데이터 동기화·외부 주소 API를 시험용으로 실행하지 않는다. 실행 결과는 관련 PR의 CI를 근거로 판단한다.

## 동시 수정·운영 한계

읽는 시점이 시설별 지오코딩 직전에서 페이지 시작으로 앞당겨진다. 페이지 전체를 하나의 DB 트랜잭션 스냅샷으로 읽는 보장은 없다. 읽은 후 관리자 수정이 발생하면 지오코딩 호출이 불필요하게 추가될 수 있으며, 최종 저장은 기존 조건부 SQL과 변경 검토 경로가 보호한다. 최신 관리자 좌표·주소·숨김 시설을 덮어쓰지 않는 기존 저장 회귀를 유지한다.

4회는 좌표 메타데이터 조회 호출 수이며 전체 배치 SQL 수나 처리 시간 감소율이 아니다. 실제 운영 DB 실행 계획·처리 시간·다음 정기 동기화 결과는 운영 반영 후 별도로 관측해야 한다. 운영 배포는 기존 계정·대장 설정을 보존하는 승인된 경로를 사용한다.

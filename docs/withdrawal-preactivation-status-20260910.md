# 탈퇴 재개 전 인수 상태 — 2026-09-10 범위 정정

API #99·배치 #47 준비 배포와 복원 도구 설치 완료. 마지막 운영 확인에서 탈퇴·복구·자동 파기는 비활성이었다. 이번 범위 수정으로 기능 설정을 바꾸지 않았다.

## 활성화 조건에서 제외한 작업

- 전체 제보 3년 정리: 취소, 후보 코드 제거.
- 전체 감사 이력 기간별 정리: 취소.
- 전역 로그 90일 보관·journald 전환: 취소, 설치 후보 제거.

이 작업들은 회원 탈퇴 기능의 필수 선행 조건이 아니다. 개인정보를 제거한 업무 이력은 기간 만료로 삭제하지 않고 보존한다. [범위 결정](account-erasure-scope.md).

## 과거 확인 사실

- 운영 읽기 전용 집계: 제보 11건, 3년 경과 후보 0건. 데이터 수정 없음.
- 당시 조회한 컨테이너 6개·기본 journal에서 90일 이전 기록을 찾지 못했으나 모든 과거 사본 부재 증거는 아니다.
- 기존 Tunnel 7일·64MB, Nginx daily/rotate 14, Docker 용량 기반 회전은 변경하지 않았다.
- 전역 journal 설치는 실행 전 거부. 운영 로그 삭제와 드라이버 전환 미실행.
- 당시 배치 검사 409건 중 401 통과·8 제외, 웹 101 통과. 취소된 모의 실행 검사도 포함된 과거 수치이며 최신 검증과 구분한다.

## 남은 계정 기능 작업

1. 회원 개인정보·로컬 재생 방지 기록에 한정한 고지/시행일과 외부 잔여 사본 검토, 웹 PR·CI.
2. 보호 대장·독립 기준·writer 설정 일치와 복원 경로 인수. 준비 workflow의 활성화 차단을 단순 해제하지 않는다.
3. 별도 운영 활성화 승인.
4. 지정된 Google/Kakao 테스트 계정의 탈퇴·선택 보관·복구·파기/취소 인수.

대장 최종 정리는 별도 단계다. 모든 백업의 부재를 탈퇴 API의 직접 선행 조건으로 섞지 않는다. 개인정보 사본의 보호와 목적 종료 운영 절차는 유지한다.

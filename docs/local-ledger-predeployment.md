# 로컬 파기 대장: 준비 배포 인수

이 문서는 계정 기능을 켜는 배포가 아닌 **점검 모드 준비 배포**를 다룬다. 운영 설치·이관·main 병합은 별도 승인 대상이다.

## 상태와 경계

- 공통 파일 저장·독립 기준 검증, UID 1000 합성 컨테이너 시험 완료.
- 기존/미국 R2 및 독립 기록은 2026-09-09 01:55 KST 재조회에서 모두 0건, 동일 기준 sequence 1이었다. 과거 완료 객체를 포함한 경로를 반복 조회했고 내용/DB는 읽지 않았다.
- 이 결과는 특정 시점의 증거다. 실제 준비 배포 직전 다시 조회해야 한다. 기록이 있으면 빈 저장소 프로비저닝을 금지한다.
- `deploy/local-paused.workflow.yml`은 비활성 검토 후보다. 실제 `.github/workflows/deploy.yml`은 바꾸지 않았다. 후보의 존재는 준비 배포 완료를 의미하지 않는다.

## 순서

```text
로컬 테스트·격리 CI
        ↓
운영 설치 승인 ──→ 최신 원본/독립 기준 재확인
        ↓                  │ 불일치·기록 있음 → 중단/이관 검토
전용 폴더·새 store ID·전용 검증 도구 설치
        ↓
읽기 전용 사전 점검 (폴더/마커/소유권/빈 원본/독립 기준)
        ↓
이전 이미지·설정 보존 → API 준비 배포 → 확인 → batch 준비 배포
        ↓
여전히 점검 모드: 탈퇴·복구·자동 파기 비활성
        ↓
보관 종료·복원 하한·장애 알림·정책·테스트 계정 인수 후 별도 활성화
```

## 도구

- `render-local-deployment.mjs`: 기존 배포 구조가 변하면 중단하는 후보 생성기. R2 자격 증명을 새 환경에 넣지 않고 별도 LOCAL 승인값을 요구한다. 운영 파일 쓰기 전에 서버 사전 점검이 반드시 성공해야 한다. API 준비 배포는 Redis 재생성 없이 API만 올린다.
- `scripts/local-ledger-preflight.py` + `LocalLedgerEmptyPreflight`: 두 서비스의 점검/쓰기 비활성, 키링/복원 세대 일치, LOCAL 소유권/마커, US 원본과 로컬의 3종 기록 0건, 독립 기준 재조회 확인. stdout은 정해진 집계만 허용한다. 설치가 없거나 비어 있지 않으면 배포 중단. API → batch 초기 전환만 지원하며 이미 LOCAL인 서비스에 대한 재배포 도구가 아니다.
- `ErasureLedgerMigration`: 별도 운영 도구용 라이브러리. 기본 `dryRun()`은 쓰지 않는다. `copyApproved()`는 명시적 writer 정지 확인과 직전 ciphertext inventory hash를 요구한다. 전체 최대 10,000개 객체를 허용하며 초과하면 중단한다. 기록 1건이라도 생기면 적용 전 별도 CLI/운영 절차 검토가 필요하다.
- migration은 원본 암호문을 그대로 저장하고 완료 객체의 모든 database epoch를 검증/보존한다. 각 단계 독립 기준 재조회, 대상의 다른 내용/추가 파일 거부, 부분 실패 후 동일 바이트 재개를 지원한다. 객체·독립 기준을 삭제하거나 재설정하지 않는다.
- `installErasureTools`는 로컬 빌드 폴더에 라이브러리를 묶는 작업이다. 이름과 달리 운영 서버 설치를 수행하지 않는다.

## 아직 실행하지 않은 운영 작업

1. 승인된 운영 폴더/새 저장소 UUID/마커/잠금 파일 설치. 0700/0600, 1000:1000. 빈 폴더 자동 생성 금지.
2. 새 검증 라이브러리와 실행기를 별도 경로에 설치. 기존 복원 도구를 덮어쓰지 않는다.
3. 검증된 저장소 UUID 및 LOCAL 준비 배포 승인 변수 등록.
4. 후보 워크플로 적용/리뷰/CI 후 승인된 main 병합과 순차 준비 배포.

필수 조건이 없으면 실패시키며 이를 우회해 배포하지 않는다. 기존 R2와 암호화 키/독립 검증 기준은 보존한다. LOCAL 기록 후 예전 R2로 자동 복귀하지 않는다. 최신 대장 유실 시 과거 회원 DB 복원을 포기한다.

## 테스트 해석

배치 로컬 전체 실행 264건 중 255건 통과, 외부/별도 환경 조건 9건 건너뜀. 새 migration 검증 10건은 모두 실행됐다. API 최초 전체 실행은 Docker 부재 4건과 Windows 줄바꿈에 따른 H2 테스트 1건이 실패했다. 후자는 운영 DDL 변경 없이 LF/CRLF 양쪽을 검증하도록 테스트를 보완했다. Docker 의존 검증은 GitHub의 격리 CI 결과로 별도 확인한다. 건너뛴 운영 인수는 테스트 통과로 계산하지 않는다.

이번 작업에서 대장 보관 종료 실행기/삭제 재개 및 복원 하한, 실제 장애 알림, 정책 공개, 사용자 테스트 계정 탈퇴/복구를 완료 처리하지 않는다. 이들은 **기능 활성화** 조건이며 준비 배포 이후에도 남는다.
